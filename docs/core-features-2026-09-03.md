# 핵심 기능 이전 결과

작성일: 2026-09-03
대상 브랜치: `revival/serverless`
로드맵 단계: 5단계 핵심 기능 구현(사용자 작업 목록의 6번)

## 완료 범위

### 기록과 일정 연결

- 기록 생성·조회·수정·삭제를 SQLite 저장소와 연결했다.
- 앱의 로컬 일정 캐시에서 날짜와 응원 팀에 맞는 경기를 선택하면 상대 팀, 경기 시각, 경기장이 자동 입력된다.
- 좌석, 메모, 승·패·무 결과와 사진·티켓은 사용자가 직접 입력하거나 교체할 수 있다.
- 첨부 파일 교체 중 DB 저장이 실패하면 새 파일을 롤백하고 기존 파일을 보존한다.

### 오늘과 캘린더

- 오늘 예정된 경기를 로컬 일정 캐시에서 찾아 홈에 표시한다.
- 월간 달력에 경기와 작성된 기록을 서로 다른 상태로 표시한다.
- 선택한 경기에서 기록 작성으로 이동하거나 미래 경기의 기기 알림을 예약할 수 있다.

### 기록 모아보기와 통계

- 시즌별 전체 직관 수, 승률, 승·패·무, 결과 미입력 수, 방문 경기장 수를 계산한다.
- 승률 계산에서 무승부와 결과 미입력 경기는 제외한다.
- 사진과 티켓이 있는 기록을 카드형 히스토리로 표시하고 기록 상세로 연결한다.

### 방문 경기장 지도

- KBO 주요 경기장 9곳의 좌표를 앱에 포함하고 로컬 DB에 초기화한다.
- 기록이 있는 경기장은 방문 횟수, 최근 방문일, 승리 횟수와 함께 표시한다.
- WebView, 외부 지도 SDK, 사용자 위치 권한 없이 동작한다.

### 공유, 알림, 설정

- 기록 상세의 폴라로이드 카드를 이미지로 캡처해 운영체제 공유 시트로 전달한다.
- Notifee 기반으로 직관 예정 알림을 기기에 예약하고 설정 화면에서 확인·취소할 수 있다.
- 모든 기록, 첨부 파일, 알림, 프로필과 로컬 설정을 한 번에 삭제할 수 있다.

### 광고 배치

- 비타망고와 동일하게 온보딩에서는 광고를 숨기고, 메인 탭 화면에서만 하단 탭 바로 위에 적응형 배너를 표시한다.
- 기록 저장이 끝난 뒤에만 전면 광고를 노출하며, 광고가 준비되지 않았거나 오프라인인 경우 사용자 흐름을 막지 않는다.
- 개발 빌드는 Google 테스트 광고 단위만 사용하고, 출시 빌드는 기존 직관일기 AdMob 앱과 광고 단위를 유지한다.
- UMP 동의 결과가 광고 요청을 허용한 경우에만 SDK를 시작하며, 필요한 지역에서는 설정 화면에서 개인정보 옵션을 다시 열 수 있다.
- 출시 전 AdMob 콘솔에서 직관일기 앱의 UMP 개인정보 메시지를 게시해야 한다. 메시지가 아직 없거나 동의 상태를 확인할 수 없으면 운영 빌드는 안전하게 광고 요청을 생략한다.

## 일정 데이터 계약

다음 단계의 GitHub Pages 자동화가 생성할 일정은 현재 로컬 `games`와 `stadiums` 스키마에 적재한다. 앱 화면은 원격 서버를 직접 호출하지 않고 항상 로컬 캐시만 읽는다. 따라서 Pages 또는 수집 작업이 실패해도 마지막으로 검증된 일정 캐시를 계속 사용할 수 있다.

이번 단계에는 UI와 저장 계약, 내장 경기장 데이터, 오프라인 폴백 구조까지 포함했다. 실제 일정 JSON 생성기, 검증기, GitHub Actions와 Pages 배포는 다음 6단계(사용자 작업 목록의 7번) 범위다.

## 검증 결과

- `npm run verify`: TypeScript, ESLint, Jest 통과
- Jest: 7개 테스트 스위트, 17개 테스트 통과
- Android: Debug APK 빌드 성공
- iOS: iPhone 16 / iOS 18.3.1 Simulator Debug 빌드 성공
- iOS 런타임: 앱 설치·실행 후 오늘, 캘린더, 기록·통계, 지도, 기록 상세·편집, 알림 화면 확인
- iOS 광고 런타임: Google 테스트 배너가 메인 탭 바로 위에 표시되고 콘텐츠와 탭을 가리지 않는 것을 확인
- npm 감사: 치명적 취약점 0건. 남은 항목은 React Native·Metro 계열 의존성의 중간/높음 등급이며 강제 수정 시 React Native 주 버전 변경이 필요해 기술 기반 후속 정비로 분리한다.
