# 전면광고 도입과 월 광고수익 모델

2026-09-17. **수익 수치는 계획용 가정이며, 실측 단가·시장 평균·수익 보장이 아니다.** 계정의 실제 수익이나 사용자 개인정보는 이 문서에 포함하지 않는다.

## 삽입 위치

| 앱 | 이번 구현 | 첫 출시 상한 | 추가 검토 후보 |
|---|---|---|---|
| 찍을지도 | 사진 분석·DB 반영 완료 후 위치 정보가 있는 사진이 1장 이상일 때 사용자가 `지도 보기`를 누르는 전환 | 하루 2회, 최소 3분 간격 | 지도 이미지 내보내기를 향후 구현하면 내보내기 완료 후 복귀 시점 |
| 직관일기 | 새 기록 저장 성공 → 미리 준비된 광고 → 광고 닫힘 → 이전 화면 | 하루 2회, 최소 3분 간격 | 별도 공유 완료 화면이 생긴 뒤 그 화면의 완료 동작 |
| 비타망고 | 사용자가 오늘 마지막 영양제를 직접 체크한 뒤 홈에서 기록·추천·설정 탭으로 이동할 때 | 하루 1회 | 루틴 공유 완료 화면의 명시적 완료 동작. 공유 창 자체에는 삽입하지 않음 |

추가 후보는 현재 구현하지 않았다. 찍을지도에는 현재 지도 내보내기 기능이 없다. 직관일기는 수정 저장·저장 실패·취소 시 광고를 건너뛴다. 비타망고는 자동 레벨업 노출을 제거했고, 알림의 `먹었어요` 액션, 앱 재시작 때 복원한 완료 상태, 체크 취소와 재체크에는 광고를 새로 예약하지 않는다. 당일 최초 루틴 완료 후 바로 앱을 닫거나 공유 화면으로 가면 그 기회는 놓칠 수 있으며 강제로 회수하지 않는다.

## 공통 동작

- 설치 후 첫 유효 완료 전환은 광고 없이 진행한다. 프로세스 시작 후 90초 동안도 전면광고를 건너뛴다.
- 하루 상한과 3분 간격을 로컬 저장소에 보존한다. 화면 재진입·앱 재시작으로 초기화하지 않는다. 기기 로컬 날짜를 사용한다.
- UMP에서 요청 가능 상태를 확인하고 SDK를 초기화한 뒤에만 광고를 미리 요청한다. 개발 빌드는 Google 테스트 ID를 사용한다.
- 광고 로딩을 기다리지 않는다. 해당 전환 때 광고가 없으면 즉시 진행하고 나중에 로드돼도 자동 표시하지 않는다. 로드 후 55분이 지나면 새 광고를 준비한다.
- 광고가 열렸다면 `CLOSED`를 기다린 뒤 이동한다. SDK의 `show()` Promise 완료는 광고 닫힘을 의미하지 않는다.
- 노출 시도는 즉시 빈도 슬롯을 예약한다. SDK 실패에도 예약을 되돌리지 않는 보수적 제한이다. 저장소 오류·광고 오류가 사용자의 저장 작업을 실패시키지 않는다.
- 복용 내역·일기 내용·사진·GPS를 광고 요청의 타기팅 값으로 전달하지 않는다.

[AdMob 배치 지침](https://support.google.com/admob/answer/6066980?hl=ko), [금지되는 전면광고 구현](https://support.google.com/admob/answer/6201362?hl=ko), [SDK 구현 문서](https://docs.page/invertase/react-native-google-mobile-ads/displaying-ads).

## 운영 광고 단위

비타망고와 직관일기는 기존 iOS·Android 전면광고 단위를 사용한다. 찍을지도는 2026-09-17 iOS 전면광고 단위를 생성하고 서버 측 일일 상한도 2회로 설정했다. iOS 기본값을 코드에 연결했으며 `EXPO_PUBLIC_ADMOB_IOS_INTERSTITIAL_ID`로 명시적으로 교체할 수 있다. 찍을지도 Android는 현재 AdMob 앱/단위가 확인되지 않아 다른 앱 ID를 재사용하지 않는다. 운영 Android를 출시하려면 해당 앱과 단위를 생성하고 `EXPO_PUBLIC_ADMOB_ANDROID_INTERSTITIAL_ID`를 설정해야 한다. 개발 Android는 테스트 단위로 검증 가능하다.

## 계산식과 가정

`월 광고수익 = 평균 DAU × 일수 × (배너 실노출/DAU/일 × 배너 eCPM + 전면 실노출/DAU/일 × 전면 eCPM) ÷ 1,000`

`필요 평균 DAU = ceil(목표 월 광고수익 ÷ DAU 1명당 월 광고수익)`

[Google eCPM 정의](https://support.google.com/admob/answer/15337570?hl=en)에 따른 계산이다. 다운로드 수·MAU·광고 요청 수를 DAU나 실제 노출 수로 대체하지 않는다. 비용·세금·유료 유입 비용을 빼기 전 광고매출이며 순이익은 별도다. DAU는 한 달 동안의 일별 활성 사용자 수 평균이다.

모든 금액은 원화 가정이며 실제 환율을 조회해 환산한 수치가 아니다. USD 실적을 대입할 때는 eCPM과 목표액을 같은 통화로 맞춘다.

| 가정 | 낮은 단가 | 기준 | 높은 단가 |
|---|---:|---:|---:|
| 배너 eCPM | 200원 | 500원 | 1,000원 |
| 전면 eCPM | 2,000원 | 5,000원 | 10,000원 |
| 배너 실노출/DAU/일 | 3회 | 3회 | 3회 |

단가 민감도를 보기 위해 노출량을 고정했다. 단가와 노출량은 실제로 함께 달라질 수 있다.

| 앱 | 전면 실노출/DAU/일 가정 | 기준에서 DAU 1,000명일 때 월매출 | 배너만 있을 때 대비 |
|---|---:|---:|---:|
| 찍을지도 | 0.25회 | 82,500원 | +37,500원 |
| 직관일기 | 0.15회 | 67,500원 | +22,500원 |
| 비타망고 | 0.40회 | 105,000원 | +60,000원 |

전면 실노출은 모든 DAU가 상한만큼 본다는 뜻이 아니다. 예를 들어 찍을지도 0.25는 DAU 1,000명에서 일 250회 실노출 가정이다. `해당 동작을 완료하는 사용자 비율 × 완료 횟수 × 동의 가능 비율 × 광고 준비·노출 성공률`을 반영한 최종값으로, 최초 경험 제외·90초 유예·빈도 제한도 이미 포함한 가정이다. 여기에 fill rate를 다시 곱하면 이중 차감이다. 특히 기록/사진 추가가 드물거나 짧은 세션이 많으면 이보다 낮아진다. 직관일기는 야구 비시즌을 별도로 계산해야 한다.

## 목표 월매출별 평균 DAU: 기준 가정

| 앱 | 월 10만원 | 월 50만원 | 월 100만원 | 월 300만원 |
|---|---:|---:|---:|---:|
| 찍을지도 | 1,213 | 6,061 | 12,122 | 36,364 |
| 직관일기 | 1,482 | 7,408 | 14,815 | 44,445 |
| 비타망고 | 953 | 4,762 | 9,524 | 28,572 |

세 앱이 각각 DAU 1,000명이면 월 255,000원, 각각 3,922명이면 월 1,000,110원이다. 후자는 앱별 DAU 합계 11,766명이며 중복 사용자를 제거한 사람 수가 아니다. 동일 가정에서 배너만 있다면 앱별 DAU 1,000명당 월 45,000원이다.

| 월 100만원 목표 | 낮은 단가 | 기준 | 높은 단가 |
|---|---:|---:|---:|
| 찍을지도 | 30,304 | 12,122 | 6,061 |
| 직관일기 | 37,038 | 14,815 | 7,408 |
| 비타망고 | 23,810 | 9,524 | 4,762 |

수익 발생 자체에 최소 DAU 조건은 없다. 실제 입금은 수익 발생과 구분해야 한다. USD 계정의 기본 지급 기준은 누적 확정 수익 $100이며 본인 확인·지급 수단·지급 보류 여부 등 조건이 적용된다. [Google 지급 기준](https://support.google.com/admob/answer/2772208?hl=en).

## 검증과 출시 후 평가

1. 개발 빌드의 Google 테스트 광고로 첫 완료 제외, 90초 유예, 광고 닫힘 뒤 화면 이동, 비행기 모드, 동의 변경, 취소/저장 실패, 백그라운드 복귀, 빈도 제한을 기기에서 확인한다. 실제 운영 광고를 직접 반복 노출·클릭해 테스트하지 않는다.
2. 기존 출시 절차대로 테스트 배포를 거쳐 스토어 업데이트한다. 이 코드 작업은 스토어 배포 완료를 의미하지 않는다.
3. 출시 후 2~4주 동안 앱/OS/광고 형식별 실제 수익·실노출·eCPM과 DAU를 같은 기간/시간대 기준으로 모은다. 유효 표본이 작다면 기간을 늘린다. 코드에는 새 분석 SDK나 서버를 추가하지 않았다.
4. DAU를 측정하는 기존 수단이 없다면 스토어의 활성 기기 지표를 DAU와 동일시하지 말고 그 한계를 표시한다. AdMob 노출만으로 DAU를 역산하지 않는다.
5. 새 기록 저장률·루틴 완료율·D1/D7 재방문율·크래시 추이를 이전 버전과 비교한다. 동시기 비교군이 없으면 인과효과라고 단정하지 않는다. 유입/계절성을 고려했는데도 완료율/재방문율이 상대 5% 이상 낮아지면 노출량을 줄이는 것을 우선 검토한다. 이 기준은 운영 제안이며 원격 실험/킬스위치를 구현한 것은 아니다.

다음 계산기로 실측값을 바꿔 재계산할 수 있다.

```sh
node scripts/ad-revenue.mjs --dau=1000 --target=1000000
node scripts/ad-revenue.mjs --app=vita-mango --scenario=low
node scripts/ad-revenue.mjs --app=jjigeuljido --banner-ecpm=500 --interstitial-ecpm=5000 --banner-impressions=3 --interstitial-impressions=0.25 --days=30
```

## 이번 변경의 확인 범위

타입 검사, 전면광고 정책/수명주기 테스트 17개, iOS·Android 프로덕션 JavaScript 번들 생성에 통과했다. 이는 네이티브 IPA/AAB 빌드·기기 광고 표시·TestFlight/스토어 배포 확인과는 다르며 해당 검증/배포는 아직 수행하지 않았다.

직관일기 기존 Jest 테스트 35개와 린트도 통과했다. 최신 `revival/serverless` 작업본을 기준으로 변경했다.
