# 직관일기 로컬 저장 기반 구현 결과

작성일: 2026-09-02
대상 브랜치: `revival/serverless`
결론: 사용자 작업 없이 5단계(전체 실행 순서 기준) 완료

로드맵 문서의 번호로는 `4단계: 로컬 데이터·사진 저장`에 해당한다. 최초 보안 수습을 1단계로 세는 사용자 실행 순서에서는 5단계다.

## 구현한 저장 구조

- `matchdiary-v1.sqlite`: 프로필, 경기장, 경기, 기록, 미디어, 알림, 백업 이력, 마이그레이션 로그
- `Documents/matchdiary/media/photos`: 직관 사진
- `Documents/matchdiary/media/tickets`: 티켓 사진
- DB에는 절대 경로 대신 앱 루트 기준 상대 경로를 저장해 백업·복원 시 기기 경로가 바뀌어도 복원할 수 있게 했다.
- 각 파일에 크기와 SHA-256 체크섬을 기록해 후속 백업·복원 무결성 검사에 재사용할 수 있게 했다.

## 저장 안전성

- 사진은 선택기가 반환한 임시 경로를 참조하지 않고 앱 전용 공간에 즉시 복사한다.
- 파일 복사 후 DB 저장이 실패하면 복사본을 지운다.
- 레거시 기록과 마이그레이션 로그는 하나의 SQLite 트랜잭션으로 저장한다.
- 앱 시작 시 DB가 참조하지 않는 고아 파일을 정리한다.
- 저장 공간에 최소 20MB 여유가 없으면 복사를 시작하지 않고 기존 기록을 보존한다.
- 초기화 실패 시 기존 데이터를 지우지 않고 시작 화면에서 재시도할 수 있다.

## 기존 기기 데이터 처리

- `REVIVAL_PROFILE_V1`, `REVIVAL_RECORDS_UI_V1` 키를 SQLite로 옮긴다.
- 기존 앱의 `YYYY-MM-DD` 형식 AsyncStorage 기록을 찾아 메모, 경기장, 사진, 티켓을 옮긴다.
- 항목별 이전 완료 로그로 재시작해도 중복 생성하지 않는다.
- 롤백과 후속 자동 복구 검증을 위해 기존 AsyncStorage 원본은 삭제하지 않았다.

## UI 연결

- 기록 작성에서 직관 사진과 티켓 사진을 각각 선택·교체·제거할 수 있다.
- 저장한 직관 사진을 오늘의 폴라로이드와 기록 모아보기에 표시한다.
- 개별 기록 삭제와 설정의 전체 기록 삭제를 DB·파일 정리와 연결했다.
- 사진 선택 취소, 권한 거부, 저장 공간 부족, DB 초기화 실패 상태를 별도로 처리한다.
