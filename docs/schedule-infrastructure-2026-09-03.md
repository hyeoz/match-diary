# 경기 일정 인프라 구현 결과

작성일: 2026-09-03

대상 브랜치: `revival/serverless`

로드맵 단계: 6단계 경기 일정 인프라(사용자 작업 목록의 7번)

## 공개 데이터 저장소

- 저장소: `hyeoz/match-diary-data`
- 매니페스트: `https://hyeoz.github.io/match-diary-data/latest.json`
- 시즌 데이터: `https://hyeoz.github.io/match-diary-data/schedules/2026.json`
- 데이터 출처: KBO 공식 경기 일정 페이지

공개 저장소에는 경기 일정·결과와 팀·경기장 매핑만 둔다. 사용자 기록, 기기 식별자, 사진, API 키, 실행 로그는 포함하지 않는다.

## 자동 갱신과 안전장치

GitHub Actions는 매일 한국 시간 오전 9시 15분과 오후 6시 15분에 실행되며 필요할 때 수동 실행할 수 있다.

1. KBO 공식 일정의 정규시즌·시범경기·올스타·포스트시즌 데이터를 월별로 수집한다.
2. 팀과 경기장을 앱의 고정 식별자로 변환하고 공식 경기 ID로 중복을 제거한다.
3. 날짜·시간·점수·상태·팀·경기장·중복·최소 경기 수와 이전 파일 대비 급감 여부를 검증한다.
4. 데이터 내용이 바뀐 경우에만 `latest.json`과 시즌 파일을 갱신한다.
5. 시즌 파일의 SHA-256을 매니페스트에 기록하고 두 파일을 다시 교차 검증한다.
6. 모든 검증에 성공한 파일만 GitHub Pages에 배포한다. 수집이나 검증이 실패하면 이전 정상 파일과 배포본을 유지한다.

최초 배포된 2026년 데이터는 총 782경기이며, 완료 586경기·취소 62경기·예정 134경기로 생성됐다.

## 앱 동작

- 앱은 SQLite에 저장된 마지막 정상 일정을 먼저 표시하므로 네트워크 응답을 기다리지 않는다.
- 백그라운드에서 `latest.json`의 `dataVersion`을 확인하고 현재 버전과 같으면 시즌 파일을 다시 받지 않는다.
- 새 시즌 파일은 HTTP 상태, JSON 계약, 경기 수, 팀·경기장 매핑과 SHA-256 체크섬을 모두 확인한 뒤에만 SQLite에 반영한다.
- 원격 요청이 실패하거나 파일이 손상되면 오류를 내부 상태에만 기록하고 기존 캐시를 유지한다.
- SQLite 스키마 2에서 홈·원정 점수, 경기 상태와 비고를 보존한다.
- 오늘과 캘린더 화면에는 예정 경기의 시간·경기장, 완료 경기의 점수, 취소·연기 사유를 표시한다.
