# 직관일기 UI 리디자인 v1

작성일: 2026-09-02  
상태: v3 승인 및 1차 UI 셸 구현 완료
적용 대상: 앱 아이콘, 온보딩 및 앱 내 전체 화면

구현 결과: [UI v3 1차 구현 기록](./ui-implementation-phase1.md)

## 1. 디자인 방향

키워드는 `따뜻한 야구 다이어리`, `한눈에 읽히는 기록`, `팀에 종속되지 않는 브랜드`다.

- 기존 아이콘의 야구와 기록 의미는 유지한다.
- 현재 앱의 폴라로이드·포스트잇·손글씨 등 야구 일기 정체성을 유지하면서 정보 구조를 정돈한다.
- 팀 컬러는 현재 앱처럼 화면 정체성을 만드는 주요 액센트로 유지하되, 본문 가독성을 해치지 않는 범위에서 사용한다.
- 공통 브랜드 색은 승패, 버튼, 기록 상태에 일관되게 사용한다.
- 사진이 없는 기록도 빈 화면처럼 보이지 않도록 경기 정보와 메모가 중심이 된다.

## 2. 로고와 앱 아이콘

검토 시안: [app-icon-concept-v1.png](./concepts/app-icon-concept-v1.png)

확정 방향: [app-icon-concept-v2.png](./concepts/app-icon-concept-v2.png)

- 펼친 다이어리의 외곽을 홈 플레이트처럼 구성했다.
- 양쪽 페이지의 붉은 실밥으로 야구공을 직접 그리지 않고 야구를 표현했다.
- 하단의 녹색은 야구장 그라운드와 기록이 쌓이는 기반을 의미한다.
- 작은 크기에서도 식별되도록 글자와 세부 묘사를 제거했다.

현재 파일은 방향성 검토용 래스터 시안이다. 확정 후에는 형태를 정제한 벡터 원본과 iOS/Android 전체 아이콘 규격을 생성한다.

v2 아이콘은 펼친 일기장 대신 연필과 야구공이 하나의 하트 형태를 만드는 구성을 사용한다. 앱의 기록 의미와 시작 화면 일러스트를 직접 연결하면서 작은 크기에서도 구분되는 방향이다.

## 2-1. 팀 마스코트 이미지

폐기 시안: [mascot-set-concept-v1.png](./concepts/mascot-set-concept-v1.png) — 입체 명암과 디테일이 강해 AI 생성 이미지처럼 보이는 문제가 있다.

중간 시안: [mascot-set-concept-v2.png](./concepts/mascot-set-concept-v2.png) — 화풍은 맞지만 여우·토끼·고양이·라쿤이 실제 앱의 팀 마스코트 구성과 맞지 않아 폐기한다.

구성 정정 시안: [mascot-set-concept-v3.png](./concepts/mascot-set-concept-v3.png)

색상 피드백 반영 시안: [mascot-set-concept-v4.png](./concepts/mascot-set-concept-v4.png)

SSG 랜디 색상 참고 시안: [mascot-set-concept-v5.png](./concepts/mascot-set-concept-v5.png)

- 현재 앱의 10개 팀 순서와 `4+4+2` 선택 배열을 유지한다.
- 팀 순서에 따른 캐릭터 구성은 `강아지, 쌍둥이 사람, 마법사 사람, 독수리, 갈매기, 영웅 사람, 공룡, 호랑이, 사자, 곰`으로 고정한다.
- 강아지는 SSG 랜더스의 랜디 색 구성을 참고한 중간 명도의 회색 털, 검은 윤곽, 밝은 주둥이와 작은 빨간 포인트를 사용한다. 짙은 네이비 곰과 명도·색상으로 명확히 구분한다.
- 쌍둥이는 자주색 대신 흰색·검정 가로줄 의상을 사용한다.
- 공식 구단 로고나 실제 마스코트를 복제하지 않고 팀별 동물·판타지 단서와 대표 색만 활용한 독자 캐릭터로 만든다.
- 모든 캐릭터는 짧은 몸통, 단순한 눈·입, 한 가지 굵기의 외곽선과 평면색을 사용한다. 입체 명암, 털 질감, 광택 큰 눈은 사용하지 않는다.
- 앱 적용 검토용 최신 개별 PNG는 `docs/design/mascots/v5/`에 팀 순서대로 보관한다.

## 4. 대표 화면 콘셉트

초기 시안: [ui-direction-v1.png](./concepts/ui-direction-v1.png)

사용자 피드백 반영 시안:

- [ui-direction-v2-core.png](./concepts/ui-direction-v2-core.png): 팀 선택, 오늘, 기록 작성, 캘린더
- [ui-direction-v2-library.png](./concepts/ui-direction-v2-library.png): 기록·통계, 지도, 설정

현재 앱 직접 실행 캡처를 기준으로 다시 만든 v3 시안:

- [ui-direction-v3-core.png](./concepts/ui-direction-v3-core.png): 시작, 닉네임·10개 마스코트 직접 선택, 폴라로이드형 오늘 홈, 사진 중심 기록 작성
- [ui-direction-v3-library.png](./concepts/ui-direction-v3-library.png): 기존 구조의 캘린더, 기록·요약 통계, 지도, 독립 설정

v3는 v2의 일반적인 스포츠 대시보드 방향을 폐기하고 현재 앱의 화면 구조와 야구 일기·스크랩북 정체성을 기준으로 삼는다.

1. 온보딩·응원 팀 선택
2. 오늘 홈·다가오는 경기·최근 기록
3. 사진·티켓·점수·좌석·메모를 포함한 기록 작성
4. 월간 캘린더와 승패·기록 표시
5. 직관 횟수·승률·최근 기록
6. 방문 경기장 지도와 설정·백업 진입

시안에 포함된 구단명과 경기 데이터는 레이아웃 검토용 예시이며 실제 KBO 로고나 상표를 사용하지 않는다.

### v3 정정·확정 사항

- 팀 선택은 현재 앱의 닉네임 입력과 10개 구단 마스코트 아이콘 직접 선택 방식을 유지한다. 별도 지역 선택 단계를 추가하거나 모자형 팀 아이콘으로 교체하지 않는다.
- `오늘의 직관`은 공개 경기 일정 데이터에서 선택 팀의 당일 경기를 찾아 표시한다.
- 기록 작성의 날짜, 상대 팀, 시간, 경기장은 경기 일정에서 자동 입력하며 편집할 수 없게 한다.
- 좌석, 사진·티켓, 메모는 사용자가 직접 입력한다.
- 더블헤더처럼 같은 날짜에 경기 후보가 여러 개면 경기 선택 단계만 제공한다.
- 캘린더의 월간 그리드, 선택 날짜, 기록 표시, 하단 상세 구조는 현재 방식을 유지하고 톤앤매너만 교체한다.
- 기록 화면에는 저장된 기록을 계산한 통계가 추가된다. 통계 수치를 사용자가 직접 입력하지 않는다.
- 지도와 설정은 각각 독립 탭·화면으로 분리한다.

## 6. 내비게이션

하단 탭은 다섯 개로 통일한다.

1. 오늘
2. 캘린더
3. 기록
4. 지도
5. 설정

기록 작성은 `오늘`과 `캘린더`에서 같은 편집 화면으로 진입한다. 두 위치에 별도 저장 로직을 만들지 않는다.

`지도`에는 방문 경기장 정보만 표시하고, 백업·복원과 앱 설정은 반드시 `설정` 탭에서 제공한다.

## 6-1. 일정 기반 기록 작성 흐름

1. 사용자가 `오늘` 또는 캘린더 날짜에서 기록 남기기를 누른다.
2. 앱이 기기에 캐시된 경기 일정에서 해당 날짜의 경기를 찾는다.
3. 경기 1개면 자동 선택하고 날짜·상대 팀·시간·경기장을 읽기 전용 카드로 표시한다.
4. 더블헤더 등 경기 후보가 2개 이상이면 해당 경기만 선택하게 한다.
5. 사용자는 좌석, 사진·티켓, 메모를 입력한다.
6. 일정이 없거나 최신 일정 파일을 받지 못한 경우 임의의 경기 정보를 입력하게 하지 않고, 마지막 정상 캐시와 일정 갱신 상태를 먼저 보여준다.

화면별로 색과 간격을 직접 지정하지 않고 디자인 토큰과 공통 컴포넌트를 통해 적용한다.

## 8. 접근성 기준

- 본문 텍스트와 배경은 WCAG AA 대비를 충족한다.
- 최소 터치 영역은 44×44pt로 한다.
- 승·패·무는 색상뿐 아니라 글자와 아이콘으로 구분한다.
- 시스템 글자 크기 확대 시 버튼과 카드가 잘리지 않는다.
- 사진이 없어도 기록의 의미가 유지된다.
- 백업·복원·삭제 행동은 일반 버튼과 색·위치·확인 단계가 명확히 다르다.

## 9. 구현 순서

1. 컬러·타이포그래피·간격·아이콘 토큰
2. 공통 버튼·카드·상태 화면
3. 하단 내비게이션과 앱 셸
4. 온보딩·팀 선택
5. 오늘 홈
6. 기록 작성·상세
7. 캘린더
8. 기록·통계
9. 지도
10. 설정·백업·복원·자동 복구

화면 구현마다 iOS와 Android 캡처를 남기고, 승인된 공통 컴포넌트를 다음 화면에서 재사용한다.
