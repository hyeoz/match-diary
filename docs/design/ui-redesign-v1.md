# 직관일기 UI 리디자인 v1

작성일: 2026-09-02  
상태: 방향성 검토용 콘셉트  
적용 대상: 앱 아이콘, 온보딩 및 앱 내 전체 화면

## 1. 디자인 방향

키워드는 `따뜻한 야구 다이어리`, `한눈에 읽히는 기록`, `팀에 종속되지 않는 브랜드`다.

- 기존 아이콘의 야구와 기록 의미는 유지한다.
- 화면은 종이 일기처럼 따뜻하지만 장식보다 정보 구조를 우선한다.
- 팀 컬러는 전체 테마가 아니라 선택 팀을 나타내는 보조 색으로만 사용한다.
- 공통 브랜드 색은 승패, 버튼, 기록 상태에 일관되게 사용한다.
- 사진이 없는 기록도 빈 화면처럼 보이지 않도록 경기 정보와 메모가 중심이 된다.

## 2. 로고와 앱 아이콘

검토 시안: [app-icon-concept-v1.png](./concepts/app-icon-concept-v1.png)

- 펼친 다이어리의 외곽을 홈 플레이트처럼 구성했다.
- 양쪽 페이지의 붉은 실밥으로 야구공을 직접 그리지 않고 야구를 표현했다.
- 하단의 녹색은 야구장 그라운드와 기록이 쌓이는 기반을 의미한다.
- 작은 크기에서도 식별되도록 글자와 세부 묘사를 제거했다.

현재 파일은 방향성 검토용 래스터 시안이다. 확정 후에는 형태를 정제한 벡터 원본과 iOS/Android 전체 아이콘 규격을 생성한다.

## 3. 컬러 시스템

| 역할 | 이름 | 기준 색상 |
|---|---|---|
| 기본 배경 | Warm Ivory | `#FBF7EF` |
| 주요 텍스트·선 | Ink Navy | `#082A4A` |
| 주요 행동·패배가 아닌 강조 | Baseball Coral | `#FF514A` |
| 성공·승리·완료 | Stadium Green | `#61B978` |
| 카드 경계 | Paper Line | `#E9E3D8` |
| 보조 텍스트 | Quiet Gray | `#6F7478` |

팀 컬러는 배지, 유니폼 심볼, 일정 카드의 작은 영역에만 추가한다. 본문 배경이나 긴 텍스트에는 사용하지 않는다.

## 4. 대표 화면 콘셉트

검토 시안: [ui-direction-v1.png](./concepts/ui-direction-v1.png)

1. 온보딩·응원 팀 선택
2. 오늘 홈·다가오는 경기·최근 기록
3. 사진·티켓·점수·좌석·메모를 포함한 기록 작성
4. 월간 캘린더와 승패·기록 표시
5. 직관 횟수·승률·최근 기록
6. 방문 경기장 지도와 설정·백업 진입

시안에 포함된 구단명과 경기 데이터는 레이아웃 검토용 예시이며 실제 KBO 로고나 상표를 사용하지 않는다.

## 5. 전체 화면 목록

### 시작과 설정

- 스플래시
- 첫 사용 안내
- 응원 팀 선택
- 기존 사용자 데이터 자동 복구 안내·진행·완료

### 오늘과 기록

- 오늘 경기 있음·없음
- 오늘 기록 있음·없음
- 기록 작성
- 사진·티켓 추가와 교체
- 경기·경기장 선택
- 기록 상세
- 기록 수정·삭제
- 공유 이미지 미리보기

### 탐색과 통계

- 월간 캘린더
- 날짜별 기록 목록과 더블헤더
- 시즌·월간 승률
- 사진 중심 기록 모아보기
- 방문 경기장 지도

### 설정과 데이터

- 응원 팀 변경
- 알림 설정
- 백업 생성
- 백업 복원·중복 처리
- 전체 데이터 삭제
- 앱 정보·개인정보 처리방침

### 필수 상태

- 첫 사용·데이터 없음
- 로딩·오프라인
- 일정 갱신 실패
- 사진·카메라·알림 권한 거부
- 사진 파일 누락
- 저장 공간 부족
- 백업 파일 손상
- 복원 중 중복 기록
- 기존 데이터 없음
- 삭제·복원 확인 및 성공·실패

## 6. 내비게이션

하단 탭은 다섯 개로 통일한다.

1. 오늘
2. 캘린더
3. 기록
4. 지도
5. 설정

기록 작성은 `오늘`과 `캘린더`에서 같은 편집 화면으로 진입한다. 두 위치에 별도 저장 로직을 만들지 않는다.

## 7. 공통 컴포넌트

- `AppHeader`
- `BottomTabBar`
- `PrimaryButton`, `SecondaryButton`, `DestructiveButton`
- `GameCard`, `RecordCard`, `StatCard`
- `TeamBadge`, `ResultBadge`
- `PhotoPicker`, `TicketPicker`
- `EmptyState`, `ErrorState`, `PermissionState`
- `ConfirmSheet`, `RestoreProgressSheet`
- `CalendarDay`, `CalendarLegend`

화면별로 색과 간격을 직접 지정하지 않고 디자인 토큰과 공통 컴포넌트를 통해 적용한다.

## 8. 접근성 기준

- 본문 텍스트와 배경은 WCAG AA 대비를 충족한다.
- 최소 터치 영역은 44×44pt로 한다.
- 승·패·무는 색상뿐 아니라 글자와 아이콘으로 구분한다.
- 시스템 글자 크기 확대 시 버튼과 카드가 잘리지 않는다.
- 사진이 없어도 기록의 의미가 유지된다.
- 백업·복원·삭제 행동은 일반 버튼과 색·위치·확인 단계가 명확히 다르다.

## 9. 구현 순서

1. 컬러·타이포그래피·간격·아이콘 토큰
2. 공통 버튼·카드·상태 화면
3. 하단 내비게이션과 앱 셸
4. 온보딩·팀 선택
5. 오늘 홈
6. 기록 작성·상세
7. 캘린더
8. 기록·통계
9. 지도
10. 설정·백업·복원·자동 복구

화면 구현마다 iOS와 Android 캡처를 남기고, 승인된 공통 컴포넌트를 다음 화면에서 재사용한다.
