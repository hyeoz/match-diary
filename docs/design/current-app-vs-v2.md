# 현재 앱 화면과 UI v2 비교

기준: 2026-09-02, iOS Simulator에서 `revival/serverless` 브랜치의 기존 앱을 직접 빌드·실행해 확인했다. 서버 연결이 중단된 상태라 기록·지도 등 서버 데이터가 필요한 화면은 빈 상태와 네트워크 오류가 함께 노출된다.

## 실제 화면 캡처

- `current-app-captures/current-app-core.png`: 시작 → 팀 선택 → 기록 홈 → 기록 작성
- `current-app-captures/current-app-library.png`: 캘린더 → 기록 → 지도 → 설정

## 전체 톤앤매너 원칙

1. 전면 재설계가 아니라 현재 앱의 `야구 일기/스크랩북` 정체성을 현대화한다.
2. 선택한 구단 컬러를 주요 액센트로 사용한다. 고정 네이비·레드 브랜드로 덮지 않는다.
3. KBO 계열 굵은 제목체와 손글씨 포인트는 유지하되, 본문·버튼은 읽기 쉬운 체계로 정돈한다.
4. 캘린더, 폴라로이드, 포스트잇 같은 기존 시각 은유를 재사용한다.
5. 하단 내비게이션은 `오늘/캘린더/기록/지도/설정`의 고정 5개 탭으로 단순화하되, 기존 앱의 팀 컬러 반응성을 유지한다.

## 실행 중 확인된 별도 문제

- 서버 요청 실패가 사용자 화면에 개발용 오류 토스트로 노출된다.
- 광고 테스트 배너가 핵심 콘텐츠 위를 차지한다.
- 닫힌 기록 작성 모달도 위치 권한을 요청하는 흐름이 있다.
- 기록·지도·팀/경기장 데이터가 서버 단절 시 빈 화면이 된다.

위 문제는 UI 개편과 별개로 서버리스 전환의 첫 구현 단계에서 제거하거나 로컬 데이터로 대체해야 한다.
